阿里云《AI Agent HandBook》· 全书内容讲解

这本书只回答一个问题：
怎样让 Agent 稳定地把活干完？

大模型已经很聪明，但“聪明”不等于“能交付”。这本书讲的是模型之外的那套工程系统：怎么设计、怎么搭、怎么跑、怎么管、怎么越做越好。全书 30 章，下面按顺序讲清每一章。

先抓骨架

贯穿全书的 12 条原则

30 章内容很多，但同样的几句话在不同章节反复出现。先记住这 12 条，后面每一章都是它们在某个具体问题上的展开。

可靠性不能交给模型本身模型负责“想”。准备信息、记住进度、执行操作、检查权限、出错恢复、验证结果，都由模型之外的 Harness 负责。第 1、2、3、30 章
选“最低充分架构”能用 Workflow 解决就不用 Agent；能用单 Agent 就不上多 Agent。只有新增能力解决了真实问题，复杂度才值得。第 1、2、11、24 章
上下文是草稿纸，状态在外面模型窗口里的内容会被压缩、截断、误读。任务的真实进度、审批结果、已执行的操作，必须先写进外部状态。第 2、4、5、8 章
模型申请完成，Harness 提交完成模型说“我做完了”不算数。完成要靠证据：测试报告、文件差异、系统里真实的状态。第 4、6、10、11 章
“看得见”≠“注册了”≠“有权用”模型看到一个工具，不代表它可以调用。每次有影响的操作都要单独判定权限，而且判定点必须是模型绕不过去的地方。第 6、9、14、15 章
给多大自主权，就配多严的边界和证据工具、网络、数据、凭证给得越多，出错时的“爆炸半径”越大。自主程度的上限，由“能撤销多少”和“能证明多少”决定。第 2、14、30 章
请求成功 ≠ 任务成功 ≠ 业务结果HTTP 200、会话结束、模型自述完成，都不等于业务目标达成。业务结果（Outcome）只能由业务方或授权的验收者判定。第 9、10、13、16 章
超时 ≠ 没执行，Checkpoint ≠ 幂等请求超时可能只是回执丢了。重试有副作用的操作前，必须先查清“上一次到底有没有发生”。第 4、8、9、10 章
消息只是提醒，权威状态才是事实轮询、回调、事件通知都可能丢失或重复。收到信号后，要回去读权威的任务状态再做决定。第 10、11、12 章
外部内容是数据，不是指令网页、文档、工具返回、其他 Agent 的消息都是不可信输入。它们不能改变系统规则、授权范围和可用工具。第 5、6、9、14 章
没有证据，就不许发布改 Prompt、Skill、工具、模型或 Harness，都是一次发布，都要有可复现的评估结果，还要经过灰度和回滚准备。第 2、15、21、22 章
调优不是让 Agent 在生产里自己改自己任何自动生成的改进都只是“候选”。它必须回到构建阶段，经过评估、审批、灰度，才能进入生产。第 2、9、23、30 章
全局视角

全书地图：一个闭环，七个部分

全书按 Agent 的生命周期组织。它是一个循环，不是一条直线：调优发现的问题要回到构建阶段形成新版本；如果问题出在架构本身（比如权限模型设计错了），就要回到架构设计，而不是不停打补丁。

前言

智以致用：从造出智能，到用好智能

核心判断：“思考”正在变成一种价格不断下降、供给不断扩大的商品。就像工业革命让“力气”变得便宜，AI 正在让“认知”变得便宜。但便宜的思考不会自动变成有价值的结果。

“智以致用”三个字：“智”是可以批量生产的认知能力；“用”是能可靠交付的任务结果；中间的“以”，就是这本书要讨论的工程方法。

能回答问题Chatbot、Copilot
人判断，模型建议
→
能完成任务Agent 承担一个环节或岗位
人在关键处授权、审阅、兜底
→
能稳定完成任务能保持状态、调对工具、从失败中恢复，
行为可观察、可评估、可审计

两条主线：“全模态”是 AI 理解世界的界面（文字之外还有图像、声音、视频、代码、结构化数据）；“全栈”是智能规模化供给的经济基础（模型、芯片、网络、存储、推理、运行时、安全，任何一层的瓶颈都会被海量 Token 放大）。

工程中心的转移：模型仍然是智能的源头，但不再单独构成架构中心。真正的工程中心转向 Harness 工程：运行时与沙箱、AI 网关、工具与协议、记忆与技能资产、可观测与评估、持续学习。也就是从 “AI Native”（被 AI 增强的应用）走向 “Agent Native”（由 Agent 围绕目标动态组织起来的应用）。

AI 能写书了，为什么还要写这本？因为有四样东西 AI 给不了：

自洽的概念

Harness、Runtime、Agent、Workflow 这些词，不同人讲的不是一件事。书要建立一套统一的语言，让团队在同一个上下文里讨论。

判断

模型给的往往是“看起来合理的平均值”。取舍需要作者自己判断。

一线经验

真实生产环境里发生过什么、哪里反复出问题，来自工程师的实践，不在公开语料里。

教训

“什么不该做”比“什么可以做”更稀缺。真实的失败模式来自生产，不是模型续写出来的。
